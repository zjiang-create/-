# 01｜证据口径与设计目标

> 快照：2026-10-12。先按证据等级识别结论，再决定是否调整数值。

## 证据等级

1. **用户已确认的目标**：例如价值锚、商品数量与定价方向。它说明“想做成什么”，并不自动证明已经生效。
2. **正式源表配置**：`C:\UGit\sldh-config\Config\Excels\Tables` 的当前单元格，说明“配置了什么”；仍需核对启用条件、权重、生成结果及运行时读取链。
3. **方案工作簿**：[动物旅行团数值方案.xlsx](../动物旅行团数值方案.xlsx) 的公式、测算和备注，说明“为什么这么定、预期结果是什么”。它可能领先或落后于正式源表。
4. **游戏代码与实测**：确定实际计算、发奖与体验。这里没有执行 Unity 编译、PlayMode 或设备验证，因此本文档不把静态估计写成实测。

遇到不同口径，应写成“目标 / 工作簿 / 正式表 / 运行时待验证”四列，说明日期与具体表、行或 ID。不要择一覆盖另一项，也不要把未启用商品、历史行或占位行算进有效投放。

## 数值建立的出发点

- 以新账号、**零付费、连续活跃 30 天**为经济模拟默认情景；在线时间包含看广告时间。低、中、高活跃分别按约 5、15、30 分钟以上建立行为次数，再独立设置愿意看广告的比例。
- 先定义资源及其**产出源、消耗口、转换关系、库存**，再建每天的行为次数。每日结果至少列目标需求、实际消耗、资源缺口、期末库存；不能仅以“没有钱所以没花”得出供需平衡。
- 按关卡、任务、成长之路、收集、挑战、爬塔、广告、商店等**系统**逐项建账，最后汇总。同一奖励只归属一个来源；广告翻倍只计相对基础奖励增加的部分。
- 分开记录一次性首通和重复通关。主线首通按当天实际推进到的新关卡逐个领取，不能把一个首通奖励当作每日可重复收益。
- 战斗用“同级标准蓝卡的普攻次数”和“怪物击杀角色所需命中次数”确定起始标尺，再根据技能倍率、控制、走位与地图做体验校正。单纯的战力乘积或推荐等级不能证明某角色能通关。
- 价格锚是跨系统换算尺，不等于每个商品都必须等价；折扣与溢价要以同一锚点计算并单独标注原因。

## 复核时的最小表格

| 字段 | 要回答的问题 |
| --- | --- |
| 资源 ID / 名称 | 到底产出和消耗了什么？ |
| 系统与行为 | 由什么行为触发、每日几次？ |
| 基础/广告增量 | 哪部分原本就能拿到？ |
| 一次性/周期/上限 | 能否重复、何时重置？ |
| 目标/实际/库存 | 缺口何时出现，有没有堆积？ |
| 来源版本与状态 | 是设想、正式配置、启用、还是实测？ |

主要追查表：`D-Item-道具表.xlsx`、`G-Level-关卡表.xlsx`、`R-GameTask-任务表.xlsx`、`G-GameAdvertisement-广告数据表.xlsx`、`C-GrowthRoad-成长之路配置表.xlsx`、`X-Photo-相片表.xlsx`、`T-FloorRewards-爬塔层数奖励表.xlsx`、`T-ChallengeStarRewards-挑战星级奖励表.xlsx`、`S-Goods-商品表.xlsx` 与 `X-systemConfiguration-系统配置表.xlsx`。详见 [06-关卡与系统投放.md](06-关卡与系统投放.md)。
